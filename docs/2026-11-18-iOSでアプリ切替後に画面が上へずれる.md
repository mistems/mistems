# iOS でアプリ切替後に画面が上へずれる

## 症状

iOS の PWA で、ほかのアプリに切り替えて戻ると、画面全体が上へずれたままになることがある。

- ヘッダー (タブの下線まで) がステータスバーの裏に隠れる
- 画面の下、フッターの下に背景の帯が見える

- この状態では、タイムラインをそれ以上、上へスクロールできない

直近の変更で入った不具合ではなく、以前から起きている。

## 原因の見立て (推測を含む)

- Misskey の画面は `100dvh` のルート (`ui/universal.vue` など) の中でスクロールし、ドキュメント自体はスクロールしない作りである。`body` は `overflow: clip` だが、`html` はクリップしていない (`style.scss` のコメントのとおり、Chrome の性能のため)
- iOS は、アプリの切り替えやキーボードの開け閉めのあとに、ドキュメントのスクロール位置 (ビジュアルビューポートの位置) をずらしたまま戻さないことがある。WebKit には同じ症状の報告がある
  - Bug 137145「Standalone mode shifts the web app content up」(ステータスバーの高さぶん上へずれ、下に空白ができる)
  - Bug 232239「Viewport offset after soft keyboard dismiss on PWA on iPad」
- 上へずれ、下にルートの外側の背景が見えるのは、ドキュメントがスクロールした状態と見た目が一致する
- それ以上、上へスクロールできないことも一致する。内側のスクロール (タイムライン) は先頭まで戻っていて、外側のドキュメントのずれだけが残っている。`html` は `overscroll-behavior: none` なので、指でスクロールしてもドキュメントまで伝わらず、手では戻せない

実機で `window.scrollY` / `visualViewport.offsetTop` の値は確かめていない。

## 対処

`packages/frontend/src/utility/ios-viewport-guard.ts` を起動時に入れる (`boot/common.ts`)。

- iOS / iPadOS のときだけ動かす。判定は `base.tsx` の `safeIosViewportFixJs` と同じ
- 画面の復帰 (`visibilitychange` / `pageshow` / `focus`)、ビューポートの大きさの変化、`focusout` のあとに、ドキュメントがスクロールしていれば `window.scrollTo(0, 0)` で戻す
- キーボードが出ている間 (レイアウトビューポートとビジュアルビューポートの高さの差が 100px を超える間) は、入力欄を見せるために iOS がずらしているので戻さない
- キーボードの開け閉めの途中は高さの差が小さく、キーボードが出ていないように見えるので、大きさの変化と `focusout` では 300ms 待ってから確かめる
- 上のきっかけのあとにずれた場合に備えて、ドキュメント自体のスクロール (`scroll`) と、指を離したとき (`touchend`) にも 300ms 待って確かめる。ずれた状態で上へスクロールしようとすれば、指を離したところで戻る

## 確かめていないこと

- iOS 実機の PWA で、アプリを切り替えて戻ったときにずれが直ること
- キーボードを出したまま切り替えて戻ったとき、入力欄が隠れないこと
- `scrollTo(0, 0)` で戻らない種類のずれ (ビジュアルビューポートだけが残るもの) があるか。あれば、強制的な再レイアウトなど別の手が要る

## シミュレーターでの確認 (2026-11-19)

iPhone 18 Pro (iOS 27.3) のシミュレーターで、ホーム画面に追加した PWA を対処なしの状態で試した。どれも再現しなかった。

| 操作 | 結果 |
| --- | --- |
| タイムラインをスクロール → 別のアプリ → PWA に戻る | ずれない |
| バックグラウンド中に WebContent プロセスを終了させる | ずれない。読み込み直しになり、タイムラインは先頭に戻る (実機の症状と合わない) |
| 慣性スクロールの途中でホームへ戻る → 戻る | ずれない |
| 画面ロック → 解除 | ずれない |

実機のスクリーンショットでは、タブの下線がステータスバーの範囲 (上から約 50pt) に描かれていた。MISTEMS の PWA はステータスバーの下からページを表示する設定 (`apple-mobile-web-app-status-bar-style` を指定していない) なので、本来ここには描かれない。ページの中のスクロールではなく、iOS 側で WebView ごとずれている可能性がある。その場合、JavaScript から見える値は変わらず、上の対処は効かない。

## 調査用の表示とログ

`packages/frontend/src/utility/viewport-debug.ts` を足した。開発者モード (設定 > その他 > 開発者) のときだけ動く。

- 画面の左下に、ビューポートまわりの値と直前のイベントを出す
- イベントのたびと、値が変わったとき (1 秒ごと) に、値を localStorage (`mistems:viewportDebugLog`) に直近 100 件残す
- 対処 (`ios-viewport-guard.ts`) がスクロール位置を戻したときも、`mistems:ios-viewport-reset` としてログに残る
- Safari の Web インスペクタからは `window.__mistemsViewportLog()` で読める

調べ終わったら、このファイルと `boot/common.ts` の呼び出しを消す。

## 2026-11-22 の見直し: ステータスバーの裏まで描く状態への切り替わり

### 実機のスクリーンショットから分かったこと

- スリープから戻ったときに起きた。ずれ幅はステータスバーの高さ (約 58pt) と同じだった
- 下のナビゲーションの位置は、正常なときと変わらなかった。画面の下に背景の帯は出ていない
- つまり、ドキュメントがスクロールしたのではなく、WebView がステータスバーの裏まで広がり、上の余白が無くなった状態とみられる。`ios-viewport-guard.ts` (スクロール位置を 0 に戻す対処) では直らない

### WebKit の報告

- [Bug 301994](https://bugs.webkit.org/show_bug.cgi?id=301994)「REGRESSION (iOS 26.1): Status bar remains visible in fullscreen mode in Home Screen Web apps」(REOPENED)
  - ホーム画面の Web アプリで、ステータスバーの扱いが「帯を出して内容をその下に描く」と「内容をステータスバーの裏まで描く」の間で、iOS の版によって切り替わっている
  - 裏まで描く版では `env(safe-area-inset-top)` が約 44pt、帯を出す版では 0 になると報告されている
  - 26.2 で一度直り、26.5.2 と iOS 27 beta で再発している
- [Bug 316008](https://bugs.webkit.org/show_bug.cgi?id=316008)「Incorrect 100vh and -lvh in standalone web apps that have not set apple-mobile-web-app-status-bar-style」(NEW)

MISTEMS は `apple-mobile-web-app-status-bar-style` を指定していないので、ふだんは「帯あり」の状態になる。スリープからの復帰で、まれに「裏まで描く」状態に切り替わり、そのまま戻らないと考えると、実機の見た目と合う。

### シミュレーターでの確認 (iPhone 18 Pro, iOS 27.3)

MISTEMS と同じ viewport (`viewport-fit=cover`) の試験ページを、ホーム画面に追加して開いた。ルートは `height: 100dvh; box-sizing: border-box; padding-top: env(safe-area-inset-top)` にした。

| ページ | safe-area-inset-top | innerHeight | ヘッダーの位置 |
| --- | --- | --- | --- |
| Safari のタブ | 0px | 714 | ステータスバーの下 |
| PWA (status-bar-style の指定なし。MISTEMS と同じ) | 0px | 812 | ステータスバーの下 |
| PWA (black-translucent。裏まで描く状態を人為的に作ったもの) | 62px | 874 | ステータスバーの下 (余白のぶん下がる) |

- 裏まで描く状態では、`env(safe-area-inset-top)` にステータスバーの高さが入る
- ふだんの状態では 0 なので、余白を足しても見た目は変わらない

### 対処

通常の UI (`ui/universal.vue`)、デッキ (`ui/deck.vue`)、ZEN (`ui/zen.vue`) のルートと、メニュー・ウィジェットのドロワー (`ui/_common_/common.vue`) に、`padding-top: env(safe-area-inset-top)` を足した。どちらの状態でも、ヘッダーがステータスバーの下に収まる。

- 未ログインの画面 (`ui/visitor.vue`) と最小の UI (`ui/minimum.vue`) には足していない。ログインして PWA で使う画面ではないため
- `ios-viewport-guard.ts` は残す。ドキュメントがスクロールしたまま残る種類のずれも、別に起こりうるため

### 確かめていないこと

- 実機で、スリープからの復帰でこの状態になったときに直ること。不具合そのものはシミュレーターで再現できていない
- 裏まで描く状態で、ステータスバーの文字の色 (帯ありのときと同じか) と、余白の背景 (`navBg`) の見え方
