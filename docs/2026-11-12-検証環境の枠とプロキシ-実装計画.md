# 検証環境の枠とプロキシ 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 検証環境を `http://dev1.localhost:3080/`〜`dev10` の固定の枠で開けるようにし、ポートの干渉・許可の確認・ログイン・HMR の課題をまとめて解く。

**Architecture:** ホストの 3080 番に置いた固定設定の Caddy が、Host の `devN` を OrbStack の独自ドメイン `devN.mistems-slot.local` に振り分ける。枠は `~/.cache/misskey-orb-dev/slots/devN/` のディレクトリで管理し、`up` で取り `down` で返す。枠が替わったら DB の中のオリジンを汎用の SQL で書き換え、`admin` のトークンを固定値にそろえる。

**Tech Stack:** bash (`orb-dev.sh`)、Caddy 2、OrbStack (docker compose・独自ドメイン)、PostgreSQL 18 (plpgsql)、vite

**Spec:** `docs/planning/2026-11-12-検証環境の枠とプロキシ.md`

## Global Constraints

- 枠は既定で `dev1`〜`dev10` の 10 個である。環境変数 `ORB_DEV_SLOT_COUNT` で数を変えられる
- プロキシのポートは `ORB_DEV_LOCALHOST_PORT` (既定 3080) である。ホストに公開するのはこの 1 つだけである
- 枠を取った環境の Misskey は、コンテナの中で `ORB_DEV_LOCALHOST_PORT` と同じ番号で待ち受ける
- OrbStack の独自ドメインは `devN.mistems-slot.local` である
- `admin` の固定トークンは `orbdevadmintoken` (16 文字の英数字) である
- `--lan` は今の動きを変えない。枠は取らない
- 生成物は `~/.cache/misskey-orb-dev/` に置き、ワークツリーには何も書かない (`files/` を除く)
- スクリプトの本籍は claudeImplement の `.claude/skills/orb-dev-server/scripts/` である
- コメントとメッセージは日本語で、既存のスクリプトの文体に合わせる

## Review Focus

1. 2 つのセッションが同時に `up` したとき、同じ枠を取らない (枠は `mkdir` の成否で決まる)
2. 枠を持ったまま web コンテナを消した環境 (`down` を通らずに `docker rm` したなど) の枠は、次の `up` で空きとして扱われる。コンテナが止まっているだけの枠は奪わない
3. 上流で `vite.config.ts` の `clientPort: 5173,` が変わったら、`up` が止まって知らせる (HMR なしで黙って起動しない)
4. 書き換えで、jsonb・配列・長さ制限のある varchar の列が壊れない。失敗したら全体が巻き戻る
5. 既存の環境 (前回 orb.local や `<project>.localhost` で動いていたもの) を `up` し直すと、前回の `url` から新しい枠の `url` に書き換わる

`lib/slots.sh`:

```bash
# 枠の台帳。orb-dev.sh から source して使う。cache_root を先に決めておくこと
#
# 枠 (devN) ごとに $cache_root/slots/devN/ を置き、中の owner に
# 「プロジェクト名」「ワークツリーのパス」「取った時刻 (UTC)」を 1 行ずつ書く。
# 枠を取るのは mkdir の成否で決めるので、並行セッションが同時に up しても同じ枠を取り合わない

slot_names="$(seq -f 'dev%g' 1 "${ORB_DEV_SLOT_COUNT:-10}" | tr '\n' ' ')"
slot_names="${slot_names% }"

# 持ち主の web コンテナがあるか。止まっているだけなら「ある」とする (Mac の再起動などで止まった環境の枠を奪わない)
slot_owner_exists() {
	docker inspect "$1-web-1" >/dev/null 2>&1
}

slot_dir() { echo "$cache_root/slots/$1"; }

slot_owner() {
	sed -n 1p "$(slot_dir "$1")/owner" 2>/dev/null || true
}

slot_of_project() {
	local s
	for s in $slot_names; do
		if [ "$(slot_owner "$s")" = "$1" ]; then
			echo "$s"
			return 0
		fi
	done
	return 1
}

slot_write_owner() {
	printf '%s\n%s\n%s\n' "$2" "$3" "$(date -u +%Y-%m-%dT%H:%M:%SZ)" > "$(slot_dir "$1")/owner"
}

# $1: プロジェクト名  $2: ワークツリーのパス  $3: 欲しい枠 (省略すると空いている最初の枠)
slot_claim() {
	local project="$1" wt="$2" wanted="${3:-}" s owner candidates
	if [ -n "$wanted" ] && [[ " $slot_names " != *" $wanted "* ]]; then
		echo "枠の名前が不正です: $wanted (使えるのは $slot_names)" >&2
		return 1
	fi
	if s="$(slot_of_project "$project")"; then
		if [ -n "$wanted" ] && [ "$wanted" != "$s" ]; then
			echo "$project は既に枠 $s を持っています。枠を替えるときは先に down してください" >&2
			return 1
		fi
		echo "$s"
		return 0
	fi
	mkdir -p "$cache_root/slots"
	candidates="${wanted:-$slot_names}"
	for s in $candidates; do
		if mkdir "$(slot_dir "$s")" 2>/dev/null; then
			slot_write_owner "$s" "$project" "$wt"
			echo "$s"
			return 0
		fi
		# 持ち主の web コンテナが無い枠は空きとして扱う。owner がまだ書かれていない (別のセッションが取っている途中) 枠は奪わない
		owner="$(slot_owner "$s")"
		if [ -n "$owner" ] && ! slot_owner_exists "$owner"; then
			rm -rf "$(slot_dir "$s")"
			if mkdir "$(slot_dir "$s")" 2>/dev/null; then
				slot_write_owner "$s" "$project" "$wt"
				echo "$s"
				return 0
			fi
		fi
	done
	if [ -n "$wanted" ]; then
		echo "枠 $wanted は $(slot_owner "$wanted") が使っています" >&2
	else
		echo "空いている枠がありません" >&2
	fi
	return 1
}

slot_release() {
	local s
	if s="$(slot_of_project "$1")"; then
		rm -rf "$(slot_dir "$s")"
	fi
	return 0
}

slot_list() {
	local s f
	for s in $slot_names; do
		f="$(slot_dir "$s")/owner"
		if [ -f "$f" ]; then
			printf '%s\t%s\t%s\t%s\n' "$s" "$(sed -n 1p "$f")" "$(sed -n 2p "$f")" "$(sed -n 3p "$f")"
		else
			printf '%s\t-\t-\t-\n' "$s"
		fi
	done
}
```

`seed/rewrite-url.sql`:

```sql
-- DB の中の Misskey のオリジン (url から末尾の / を除いたもの) を書き換える。
-- 添付・アバター・絵文字などの URL は絶対 URL で残るので、環境の url を変えたら (枠を替えた、restore した) これで直す。
-- 書き換える列は決め打ちにせず、public スキーマの通常のテーブルの文字列・json・文字列の配列の列をすべて見る。
-- usage: psql -v ON_ERROR_STOP=1 -v old=<古いオリジン> -v new=<新しいオリジン> < rewrite-url.sql
BEGIN;
-- psql の変数は DO の本体の中では展開されないので、トランザクションの設定値で渡す
SELECT set_config('orb.old', :'old', true), set_config('orb.new', :'new', true) \gset
DO $$
DECLARE
	r record;
	o text := current_setting('orb.old');
	n text := current_setting('orb.new');
	cnt bigint;
	total bigint := 0;
BEGIN
	IF o = '' OR n = '' OR o = n THEN
		RAISE NOTICE '書き換えません (old=%, new=%)', o, n;
		RETURN;
	END IF;
	FOR r IN
		SELECT c.relname AS tbl, a.attname AS col, format_type(a.atttypid, a.atttypmod) AS typ
		FROM pg_attribute a
		JOIN pg_class c ON c.oid = a.attrelid
		JOIN pg_namespace ns ON ns.oid = c.relnamespace
		WHERE ns.nspname = 'public' AND c.relkind = 'r'
			AND a.attnum > 0 AND NOT a.attisdropped AND a.attgenerated = ''
			AND a.atttypid IN ('text'::regtype, 'varchar'::regtype, 'json'::regtype, 'jsonb'::regtype, 'text[]'::regtype, 'varchar[]'::regtype)
	LOOP
		EXECUTE format('UPDATE public.%I SET %I = replace(%I::text, $1, $2)::%s WHERE strpos(%I::text, $1) > 0',
			r.tbl, r.col, r.col, r.typ, r.col) USING o, n;
		GET DIAGNOSTICS cnt = ROW_COUNT;
		total := total + cnt;
	END LOOP;
	RAISE NOTICE '% を % に書き換えました (% 行)', o, n, total;
END $$;
COMMIT;
```

`\gset` は結果を捨てるために使う (`set_config` の値を表示しない)。

usage のコメント (2〜20 行目) の `up` の説明を次に置き換える。

```bash
#   up        設定を生成して起動し、起動完了を待って URL を表示する (初回は管理者アカウントも作る)
#             空いている枠 (既定は dev1〜dev10) を取り、http://<枠>.localhost:3080/ で開けるようにする。--slot=devN で枠を指定できる。
#             枠が埋まっていれば起動しない。--no-slot なら枠を取らず http://web.<プロジェクト名>.orb.local:3000/ で起動する
#             --lan を付けると、LAN 内の端末 (スマホの実機など) から http://<Mac の LAN の IP アドレス>:<ポート> で開けるようにする (枠は取らない)
#             --lan-mdns は IP アドレスの代わりに <Mac のホスト名>.local を使う (Android の Chrome は .local を引けない)
#             --prod を付けると pnpm dev の代わりに本番ビルド (pnpm build → migrate → start) で起動する
#             --seed を付けると、起動後にキーの合うスナップショットがあれば restore、なければ seed を実行する
#   down      停止して枠を返す。-v を付けると DB・node_modules の volume も消す
#   slots     枠の一覧を表示する
```

`*.localhost の共用プロキシ` のコメントブロック (`localhost_port=` の上) を次に置き換える。

```bash
# 枠と共用プロキシ
# 枠 (devN) を取った環境は、Misskey の url を http://devN.localhost:<localhost_port>/ にする。
# ブラウザは *.localhost を 127.0.0.1 に向けるので、ホストの 127.0.0.1:<localhost_port> に 1 つだけ置いた Caddy が、
# Host の 1 つ目のラベル (devN) で devN.mistems-slot.local (web コンテナに付けた OrbStack の独自ドメイン) へ振り分ける。
# 枠と環境の対応は独自ドメインのラベルで決まるので、Caddy の設定は変わらない。
# Misskey はコンテナの中でも <localhost_port> で待ち受け、web コンテナでは devN.localhost を 127.0.0.1 に向ける。
```

```bash
# 枠を取って url を枠のものにする。取れなければ枠の一覧を表示して終了する
use_slot() {
	if ! slot="$(slot_claim "$project" "$wt" "$want_slot")"; then
		echo "枠の一覧:" >&2
		print_slots >&2
		echo "空けるときは、使っていない環境を '$0 down <worktree>' で止めてください。枠を取らずに起動するなら --no-slot を付けます" >&2
		exit 1
	fi
	ensure_proxy
	url="http://$slot.localhost:$localhost_port/"
	listen_port="$localhost_port"
}

print_slots() {
	local s p w t state
	printf '%-6s %-32s %-10s %s\n' 枠 プロジェクト 状態 URL・ワークツリー
	while IFS=$'\t' read -r s p w t; do
		if [ "$p" = "-" ]; then
			printf '%-6s %-32s %-10s %s\n' "$s" - 空き -
		else
			state="$(docker inspect -f '{{.State.Status}}' "$p-web-1" 2>/dev/null || echo なし)"
			printf '%-6s %-32s %-10s %s\n' "$s" "$p" "$state" "http://$s.localhost:$localhost_port/  $w (取得 $t)"
		fi
	done < <(slot_list)
}

# vite.config.ts の HMR の接続先のポート (clientPort) を、プロキシのポートに置き換えたコピーを作る。
# 機能ブランチは origin/develop から切るので、vite.config.ts を変えるコミットを置けない。コンテナの中でだけ重ねる
write_vite_overlays() {
	local pkg port src
	for pkg in frontend:5173 frontend-embed:5174; do
		port="${pkg#*:}"
		pkg="${pkg%%:*}"
		src="$wt/packages/$pkg/vite.config.ts"
		if ! grep -q "clientPort: $port," "$src"; then
			echo "$src に 'clientPort: $port,' がありません。上流で vite の設定が変わったので、orb-dev.sh の write_vite_overlays を直してください。" >&2
			echo "HMR がつながらないまま起動しないよう、ここで止めます。" >&2
			exit 1
		fi
		sed "s/clientPort: $port,/clientPort: $localhost_port,/" "$src" > "$state_dir/vite.config.$pkg.ts"
	done
}

# 枠を取った環境の web サービスに足す行。$1 が variant なら vite の重ねマウントを出さない (本番ビルドなので使わない)
slot_entries() {
	[ -n "$slot" ] || return 0
	printf '    labels:\n      dev.orbstack.domains: "%s.%s"\n' "$slot" "$slot_domain"
	printf '    extra_hosts:\n      - "%s.localhost:127.0.0.1"\n' "$slot"
}

slot_vite_mounts() {
	[ -n "$slot" ] && [ -z "$prod" ] || return 0
	printf '      - ./vite.config.frontend.ts:/workspace/packages/frontend/vite.config.ts:ro\n'
	printf '      - ./vite.config.frontend-embed.ts:/workspace/packages/frontend-embed/vite.config.ts:ro\n'
}

# DB の中のオリジンを書き換える。$1: 古い url  $2: 新しい url (どちらも末尾の / はあってもなくてもよい)
rewrite_origin() {
	local old="${1%/}" new="${2%/}"
	[ -n "$old" ] && [ "$old" != "$new" ] || return 0
	echo "DB の中の $old を $new に書き換えます..."
	psql_db -v old="$old" -v new="$new" < "$script_dir/seed/rewrite-url.sql"
	compose exec -T redis redis-cli FLUSHALL > /dev/null
}

# admin のトークンを全環境で同じ固定値にする。ブラウザは枠のホスト名ごとにトークンを覚えているので、
# 枠につなぐ環境を替えてもログインしたままになる
set_admin_token() {
	psql_db -q -c "UPDATE \"user\" SET token = '$admin_token' WHERE \"usernameLower\" = '$admin_user' AND host IS NULL" > /dev/null
}

# 前回 up したときの url (生成済みの default.yml から読む)。初めてなら空
previous_url() {
	sed -nE 's/^url: *//p' "$state_dir/default.yml" 2>/dev/null || true
}
```

### 計画から変えたこと

- Caddy は、`devN` 以外のホストを以前どおり `web.<project>.orb.local:3000` へ回す。以前の版で `<project>.localhost` の url で動いている環境 (mistems-main、favstarandtimemachine) を、`up` し直すまで開けるようにするため
- 書き換えの SQL は、長さ付きの型 (`varchar(512)` など) を長さを外した型にキャストする。明示的なキャストは黙って切り詰めるため (テストで見つかった)
- 書き換えの SQL は、URL エンコードされた形のオリジン (アバターのプロキシの `url=`) も書き換える
- `admin` のトークンは web の起動前にもそろえ、そろえたら `userTokenRegenerated` の内部イベントを Redis で流す。Misskey はトークンからユーザーを引いた結果を、見つからなかった場合も含めて 5 分間メモリに残すため
- variant の起動でも `admin` のトークンをそろえる (種類 2 はベースの DB、種類 3 は vdb)
- 既存の `wait_ready` の `grep -q` が `pipefail` で SIGPIPE になり、起動済みの環境の `up` が 15 分待ち続けていたのを直した

### 残った課題

- OrbStack の VM のメモリ (12GB) とスワップ (13GB) が満杯に近く、検証中に announcement-groups の vite が OOM で止まった (終了コード 137)。dmesg にも node のプロセスが OOM で止められた記録が残っている。枠は 10 個あるが、同時に起動処理をする環境が重なると足りない。OrbStack の VM のメモリを増やすか、使っていない環境を止める運用が要る
- variant の起動でトークンをそろえる処理は、メモリ不足のため実環境での確認を省いた (通常の環境の経路は確認した)
- `pnpm dev` の起動で `misskey-js` のビルドが 2 本同時に走り、`ENOTEMPTY` で失敗することがあった (やり直すと通った)。今回の変更とは関係なく、以前からある
