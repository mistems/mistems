# ハッシュタグをメニューからミュートする（hashtag-mutable の作り直し）

作成: 2026-11-12。ブランチ `feat/hashtag-mute-menu`（最新の `origin/develop` から切った）。

## 目的

ノートの本文のハッシュタグを右クリック（スマホでは長押し）したメニューから、そのハッシュタグをワードミュート・ハードワードミュートできるようにする。

## 元のブランチ（`hashtag-mutable`）と、作り直した理由

- 元のブランチは、MkA を丸ごと複製した 205 行の `MkHashtag.vue` を作り、`MkMfm.ts` のハッシュタグの描画をそれに差し替えていた
- 本家で MFM の描画が `createMfmRenderer`（`packages/frontend-shared/js/mfm-renderer.ts`）に共通化され、`MkMfm.ts` の変更が当たらなくなったので、2026-10-23 に統合から外していた
- 元の実装は、ミュートする語を `tag`（`#` なし）で登録していた。ワードミュートは本文の部分一致なので、タグ以外で同じ語を含むノートまで隠れていた

## 作り直した形

- `mfm-renderer.ts` の部品に、省略できる `Hashtag` を足した。指定したときだけ、ハッシュタグを `Hashtag` で描画し、`A` の props に加えて `hashtag`（`#` を除いたタグ）を渡す。指定しなければ今までどおり `A` で描画するので、埋め込み（`frontend-embed`）は変わらない
- MkA に、右クリックのメニューの末尾へ項目を足す `extraMenuItems`（開くたびに呼ぶ関数）を足した。足す項目がなければ区切り線も足さない
- `MkHashtag.vue` は MkA を包むだけの部品にした。サインインしているときだけ、`#タグ` の見出しと「ワードミュート」「ハードワードミュート」を足す。すでにミュートしている種類は出さない
- ミュートは正規表現で登録する: `/#タグ(?:[^\p{L}\p{N}_]|$)/iu`
  - ハッシュタグは大文字・小文字を区別しないので `i` を付ける。`#Misskey` も隠れる
  - タグの続き（文字・数字・`_`）が来るものは除く。`#misskey` で `#misskeyio` は隠れない
  - サーバーの RE2 は先読みに対応していないので、先読みを使わずに書いた。RE2 と JavaScript の `RegExp` で判定が一致することを確かめた
  - タグの中の正規表現の記号はエスケープする
- 登録は設定画面と同じ `os.apiWithDialog('i/update', ...)` で行う。登録したものは、設定のワードミュートの欄に正規表現として並ぶので、そこで外せる

## やっていないこと

- iOS の Safari は、リンクの長押しで `contextmenu` を出さず、OS のリンクのメニューを出す。元のブランチは独自のタッチ処理でこれを置き換えていたが、MkA のふつうのリンクの挙動を変えることになるので、作り直しでは入れていない。Android の Chrome とパソコンでは右クリック・長押しでメニューが出る

## テスト

- `packages/frontend/test/unit/hashtag-mute-menu.test.ts`（6 件）: メニューに 2 つの項目が出て正規表現で登録すること、正規表現がそのハッシュタグだけに当たること、記号のエスケープ、ミュート済みの種類は出さないこと、サインインしていなければ出さないこと、ふつうのリンクのメニューが変わらないこと。修正前のコードでは 2 件が失敗する
- `vue-tsc`: frontend と frontend-embed の両方が通る
- `vue-component-reviewer` の指摘（Storybook の併設、ミュートの照合のずれ）を直した
