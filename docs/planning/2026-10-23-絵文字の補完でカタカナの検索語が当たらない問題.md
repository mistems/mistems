# 絵文字の補完でカタカナの検索語が当たらない問題

**ブランチ:** `emojiPickKanaConv`（「絵文字検索ひらカナ大統一」）

## 背景

`emojiPickKanaConv` は、カスタム絵文字のエイリアス（ヨミ）をひらがな・小文字にそろえ、絵文字ピッカーの検索語も同じようにそろえることで、ひらがなとカタカナのどちらで探しても当たるようにした。

ところが、エイリアスを書き換えるのは `custom-emojis.ts` で、絵文字一覧を持つ全員に効く。一方で、検索語をそろえたのは絵文字ピッカー（`MkEmojiPicker.vue`）だけである。そのため、ほかの検索の入口では、カタカナの検索語がエイリアスに当たらなくなっていた。

| 入口 | 検索語の扱い | 結果 |
|---|---|---|
| 絵文字ピッカー（`MkEmojiPicker.vue`） | ひらがなにそろえる | 当たる |
| 投稿フォームの補完（`:` で始まる入力、`MkAutocomplete.vue`） | そのまま比べる | エイリアスが「ねこ」になった絵文字を `:ネコ` で探しても当たらない |
| 絵文字一覧のページ（`pages/about.emojis.vue`） | そのまま完全一致で比べる | 同上 |

上流のまま（正規化なし）なら、エイリアスがカタカナで登録された絵文字は `:ネコ` で当たっていた。この意味で、上流からのデグレになっている。2026-10-23 に MISTEMS.113 と 114 の差分を調べた際に見つかった（114 で新たに起きたものではない）。

## 方針

- 新しいユーティリティ `packages/frontend/src/utility/kana-to-hira.ts` を足す
  - `toKanaToHira(str)`: カタカナをひらがなにする（既存の実装と同じ変換）
  - `searchEmojiKanaInsensitive(query, emojiDb, max)`: 元の検索語で `searchEmoji` を引き、検索語をひらがな・小文字にそろえた語が元と違えば、そちらでも引いて結果をまとめる（重複は除き、元の検索語の結果を先に並べる）。元の検索語でも引くのは、Unicode 絵文字の名前やカタカナのままのエイリアスにも当てるため
- `MkAutocomplete.vue` の絵文字補完は `searchEmojiKanaInsensitive` を使う
- `about.emojis.vue` の検索は、元の検索語に加えて、ひらがな・小文字にそろえた検索語でもエイリアスを比べる
- `custom-emojis.ts` と `MkEmojiPicker.vue` にある既存の `toKanaToHira` には手を付けない。`party/17758-emoji-cache` との統合で rerere が覚えている解消方法を崩さないためである。共通化は、`party/17758` が上流に入って統合の形が落ち着いてから行う

## 確認

- 単体テスト（`packages/frontend/test/unit/kana-to-hira.test.ts`）
  - `toKanaToHira` がカタカナをひらがなにし、ひらがな・英数字・記号は変えない
  - エイリアスが「ねこ」のカスタム絵文字を、`ネコ`、`ねこ`、`neko` で探すと当たる
  - カタカナの名前を持つ項目は、元の検索語（カタカナ）で当たる
  - 結果に同じ絵文字が重複しない。件数が `max` を超えない
- frontend の型チェックと、変更ファイルへの eslint
