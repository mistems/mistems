# お知らせのグループとタブ

作成日: 2026-10-26
ブランチ: `feat/announcement-groups`（origin/develop から作成）

## 目的

- お知らせを「重要なお知らせ」「ユーザーイベント」などのグループに分け、お知らせのページでタブを切り替えて読めるようにする
- グループの中身（どんなグループがあるか、どのお知らせをどのグループに入れるか）は、コントロールパネルで設定する
- 利用者は、グループ（タブ）ごとに非通知にできる

## 今の作り（origin/develop）

- お知らせは `packages/backend/src/models/Announcement.ts`（`announcement` の表）。項目は、タイトル・本文・画像・アイコン・表示の形（normal / banner / dialog）・既読の確認・有効かどうか・自動のアーカイブ・既存の利用者向けか・`silence`（通知しない）・特定の利用者向け（`userId`）
- 未読の判定は `AnnouncementService.getUnreadAnnouncements`。`silence = false` のものだけを未読として数え、バッジ・バナー・ダイアログを出す
- お知らせのページ `packages/frontend/src/pages/announcements.vue` のタブは「現在」と「過去」の 2 つ
- 管理は `packages/frontend/src/pages/admin/announcements.vue` と `admin/announcements/{create,update,delete,list}`
- MISTEMS では `party/15049-announce-reset-reads`（既読のリセット）がお知らせに触れている。統合のときのコンフリクトに注意する

## 作るもの

### 1. グループ（backend）

- 新しい表 `announcement_group`: `id`、`name`（表示名）、`icon`（tabler のアイコン名、任意）、`order`（並び順）、`createdAt`、`updatedAt`
- `announcement` に `groupId`（null 可、グループを消したら null に戻す）を足す。グループに入っていないお知らせは「その他」として扱う
- 管理用の API: `admin/announcements/groups/create`・`update`・`delete`・`list`。権限は、お知らせの管理と同じ（`canManageAnnouncements` 相当、既存の admin/announcements に合わせる）
- `admin/announcements/create`・`update` に `groupId` を足す。`announcements`（一覧）に `groupId` での絞り込みを足す
- 利用者向けのグループの一覧の API（`announcements/groups`、ログインなしでも読める）
- モデレーションログに、グループの作成・変更・削除を記録する

### 2. 利用者ごとの非通知（backend）

- `user_profile` に `mutedAnnouncementGroupIds`（文字列の配列、既定は空）を足す。「その他」も非通知にできるよう、特別な値（例: `'ungrouped'`）を使う
- `i/update` で変更できるようにする（またはお知らせ専用の API。既存の作りに近いほうを選ぶ）
- 非通知にしたグループのお知らせは、その利用者にとって `silence` と同じ扱いにする: 未読に数えず、バッジ・バナー・ダイアログを出さない。タブの中では普通に読める
- ただし、既読の確認が必要なお知らせ（`needConfirmationToRead`）と、特定の利用者向けのお知らせは、非通知の対象にしない（運営からの確実な連絡を落とさないため）

### 3. お知らせのページ（frontend）

- タブを「すべて」・グループごと（`order` の順）・「その他」（グループに入っていないお知らせがあるときだけ）にする。グループが 1 つも無いときは今と同じ見た目にする
- 「現在」と「過去」の切り替えは、タブの中の切り替え（セグメント）に移す
- 各グループのタブ（「すべて」以外）に、非通知の切り替え（ベルのアイコン）を置く。非通知のタブには、それと分かる印を付ける
- 設定のページ（通知の設定の近く）にも、グループごとの非通知の切り替えを置く

### 4. コントロールパネル（frontend）

- お知らせの管理のページに、グループの管理（追加・名前とアイコンの変更・並べ替え・削除）を足す
- お知らせの作成・編集で、グループを選べるようにする。一覧でグループごとに絞り込めるようにする

## 確かめ方

- コントロールパネルで「重要なお知らせ」「ユーザーイベント」を作り、お知らせをそれぞれに入れると、お知らせのページにタブが出て、切り替えて読める
- 利用者が「ユーザーイベント」を非通知にすると、そのグループの新しいお知らせではバッジ・ダイアログが出ない。タブを開けば読める
- 既読の確認が必要なお知らせは、非通知のグループでも通知される
- グループを消すと、そのお知らせは「その他」に移る
- グループが 1 つも無いサーバーでは、お知らせのページが今と同じに見える

## 決めたこと（変えるならここ）

- 非通知は、そのグループのお知らせを `silence` と同じ扱いにする（読めるが、知らせない）
- 既読の確認が必要なお知らせと、特定の利用者向けのお知らせは、非通知にできない
- 「現在」と「過去」は、タブの中の切り替えに移す

## 決めていないこと

- 最初から用意しておくグループ（無しで始め、管理者が作る想定）
- グループの公開範囲（ロールごとに見せるグループを変えるなど）は入れない
