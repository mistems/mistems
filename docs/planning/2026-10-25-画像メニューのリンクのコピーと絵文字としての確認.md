# 画像メニューのリンクのコピーと、絵文字としての確認

作成日: 2026-10-25
ブランチ: `feat/image-menu-copy-link-emoji-preview`（origin/develop から作成）

## 目的

1. スマホで、ノートの画像のリンク（URL）を取りにくい。サムネイルの「…」メニューから、リンクをコピーできるようにする
2. 画像を絵文字として登録したらどう見えるかを、登録する前に確かめられるようにする。画像の「…」メニューに「絵文字として確認」を足し、ダミーのノートを並べた画面で、本文とリアクションでの見え方を 1 画面で確かめる

## 今の作り

- サムネイルの「…」は `packages/frontend/src/components/MkMediaImage.vue` の `showMenu` が開く
- メニューの中身は `packages/frontend/src/utility/get-file-menu.ts` の `getFileMenu(file, onHideStateUpdated)` が作る。今の項目は「隠す」、センシティブの切り替え（モデレーター）、ファイルの詳細（自分のファイル）、モデレーション（モデレーター）、開発者モードの ID のコピーである
- 「リンクをコピー」はどこにも無い

## 作るもの

### 1. 「リンクをコピー」

- `getFileMenu` に、誰でも使える項目として足す。位置は「隠す」の直後
- コピーする URL は `file.url`（ブラウザで開ける元の画像）。コピーしたら、ほかのコピーの操作と同じ完了の表示を出す（`copyToClipboard` と既存の通知の出し方に合わせる）
- アイコンは `ti ti-link`。文言は既存の i18n のキー（「リンクをコピー」相当のもの）があれば使い、無ければ `locales/ja-JP.yml` に足す

### 2. 「絵文字として確認」

- `getFileMenu` に、画像（`file.type` が `image/` で始まるもの）のときだけ出る項目として足す。アイコンは `ti ti-mood-smile` など
- 押すと、ダイアログ（スマホでは全画面）を開き、ダミーのノートを 4 つ並べる

#### ダミーのノート

1 つのノートの中身は次のとおりとする。

```
1 行目: 絵文字 1 個
2 行目: 絵文字 3 個を続けて
リアクション: その絵文字（数は 1 などの適当な値）
```

- 絵文字の画像には、その画像の URL を使う。絵文字としては登録されていないので、MFM の `:name:` ではなく、URL を直接渡して描画する（`MkCustomEmoji` などの既存の描画部品が URL を受け取れるなら使う）
- アバター、名前、時刻などは、ノートらしく見える程度のダミーで良い（本物の `MkNote` は API を呼ぶので使わず、見た目だけの部品を作る）
- 新しい部品は `MkEmojiPreview*` の名前にし、Storybook の stories を併設する（working-on-frontend の規約）

#### 並べ方

| | 1 つめ | 2 つめ |
| --- | --- | --- |
| ライト | 今使っているライトのテーマ | Misskey の既定のライトのテーマ |
| ダーク | 今使っているダークのテーマ | Misskey の既定のダークのテーマ |

- 4 つのノートを 1 画面に収める。広い画面では 2 × 2、狭い画面では縦に 4 つ並べ、スクロールせずに見えることを目標にする
- それぞれのノートには、そのテーマの CSS 変数を、ノートを囲む要素にだけ当てる。ページ全体のテーマは変えない
- 今使っているテーマと既定のテーマが同じときも、2 つ並べる（区別のため、テーマの名前を小さく添える）

#### 大きさ

- 文字の大きさ・絵文字の大きさ・リアクションの大きさは、利用者の設定（文字の大きさ、リアクションの表示の大きさなど）によらず、「中」に固定する

## 確かめ方

- スマホの幅で、ノートの画像の「…」から「リンクをコピー」を押すと、画像の URL がクリップボードに入る
- 「絵文字として確認」を押すと、4 つのダミーのノートが 1 画面に並び、1 行目に 1 個、2 行目に 3 個、リアクションに 1 個の絵文字が出る
- 利用者の文字の大きさを「大」や「小」にしても、ダミーのノートの大きさは変わらない

## 決めたこと（変えるならここ）

- 「ライト 2 ノート・ダーク 2 ノート」の 2 つずつは、今使っているテーマと、Misskey の既定のテーマにした
- 「絵文字として確認」は画像のときだけ出す。動画や音声では出さない

## 決めていないこと

## 検証結果

2026-10-25 に、OrbStack の開発環境 (`http://web.image-menu-emoji-preview.orb.local:3000/`、seed 入り) で、Playwright (Chromium) を使って確かめた。admin でログインし、user02 の画像付きのノートを開いて、サムネイルの「…」から操作した。

### 実装したもの

- `get-file-menu.ts`: 「隠す」の直後に「リンクをコピー」(`ti ti-link`、既存のキー `copyLink`) を足した。`copyToClipboard(file.url)` でコピーし、ほかのコピーと同じトーストを出す。画像のときだけ「絵文字として確認」(`ti ti-mood-smile`) を足した
- `MkEmojiPreviewDialog.vue`: `MkModalWindow` でダミーのノートを 4 つ並べる。スマホ (deviceKind が smartphone) では MkModalWindow の既定どおりドロワー (ほぼ全画面) になる。本文の幅が 600px 以上なら 2 × 2、未満なら縦に 4 つ並べる
- `MkEmojiPreviewNote.vue`: 見た目だけのダミーのノートである。アバター・名前は今のアカウント、時刻は開いた時刻にした。絵文字は `MkCustomEmoji` に `url` を渡して描画し (登録済みの絵文字と同じく media proxy の `emoji` 形式を通る)、ミュートの判定は無視する。リアクションは `MkReactionsViewer.reaction.vue` の「中」の大きさ (高さ 42px、`font-size: 1.5em`、幅の制限 70px) を写した
- テーマは、ライト・ダークそれぞれ「今のテーマ (`prefer.s.lightTheme` / `darkTheme`、未設定なら既定)」と「既定のテーマ (`l-light` / `d-green-lime`)」を使う。`theme.ts` に切り出した `compileTheme` と `compiledThemeToCssVars` で、ダミーのノートの root の style にだけ `--MI_THEME-*` を当てる
- 大きさは、root の `font-size` を 14px (文字の大きさの設定の既定) に固定し、`reactionsDisplaySize` などの設定を読まないことで固定した。ノートの中の大きさは `MkNote.vue` と同じコンテナクエリで、幅に応じて変わる (本物のノートと同じ見え方にするため)
- i18n は `_emojiPreview` (`title` / `currentTheme` / `defaultTheme`) を `ja-JP.yml` に足した
- Storybook の `MkEmojiPreviewNote.stories.impl.ts` と `MkEmojiPreviewDialog.stories.impl.ts` を併設した

### 気になる点

- 開発環境では、今のテーマと既定のテーマが同じ (Mi Light / Mi Green+Lime Dark) なので、同じ見た目のノートが 2 つずつ並ぶ。テーマを変えた環境での見た目は、スクリーンショットでは確かめていない
- 「既定のテーマ」は Misskey 本体の既定 (`l-light` / `d-green-lime`) である。サーバーの管理者が設定した既定のテーマ (`instance.defaultLightTheme` など) ではない
- 2 行目の 3 個は、MFM で `:a::a::a:` と続けて書いたときと同じく、すき間なしで並ぶ
