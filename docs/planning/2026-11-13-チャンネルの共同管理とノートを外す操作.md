# チャンネルの共同管理とノートを外す操作

- 作成日: 2026-11-13
- ブランチ: mkPostFormExtend (チャンネル投稿・チャンネル連合と同じブランチで扱う)
- 状態: 未着手。先に「ノートを外す操作」を取り除いた (§1)

## 1. 経緯

チャンネル連合のハッシュタグ ([2026-11-13-チャンネル連合-ハッシュタグ.md](2026-11-13-チャンネル連合-ハッシュタグ.md)) では、同じハッシュタグを付けたリモートの公開ノートを、だれでもチャンネルに入れられる。その対策として、チャンネルのオーナーとサーバーのモデレーターが、収蔵したリモートのノートをチャンネルから外す操作 (`channels/remove-note`、ノートのメニューの「チャンネルから外す」) を足していた。

この操作はいったん取り除いた。理由は次のとおりである。

- チャンネルのオーナーは 1 人に固定で、交代する手段がない。そこにモデレーションの役目を持たせると、オーナーを過度に縛り付けてしまう
- モデレーションの権限は、オーナーの交代や共同管理者の仕組みとセットで持たせるべきである
- 共同管理の仕組みは作るものが多いので、計画書として残し、あとで取り組む

取り除く直前の実装は、mkPostFormExtend のコミット c77c08b81b にある。取り除いたものは次のとおりで、戻すときはこのコミットから取り出せる。

- `packages/backend/src/server/api/endpoints/channels/remove-note.ts` と、`endpoint-list.ts` の登録
- `packages/frontend/src/utility/get-note-menu.ts` の「チャンネルから外す」
- `locales/ja-JP.yml` の `_channel.removeNoteFromChannel`、`_channel.removeNoteFromChannelConfirm`
- e2e の `describe('channels/remove-note')`、連合テスト H3 の後半 (外すとチャンネルのタイムラインから消えること)

取り除いたあとは、収蔵されたリモートのノートをチャンネルから外す手段はない。荒らしには、サーバーのモデレーターがふだんの手段 (ノートの削除、リモートのユーザーのサイレンスや利用停止、サーバー単位のブロック) で対応する。

## 2. ねらい

- チャンネルのオーナーを交代できるようにする
- オーナーのほかに、チャンネルの共同管理者 (以下「管理者」) を置けるようにする
- オーナーと管理者が、チャンネルの中のモデレーション (ノートを外す操作など) を分担できるようにする
- オーナーがいなくなっても (アカウントの削除・凍結、長期の不在)、チャンネルが管理されないまま残らないようにする

## 3. 役割と権限 (案)

| 操作 | オーナー | 管理者 | サーバーのモデレーター |
| --- | --- | --- | --- |
| 名前・説明・バナー・色などの編集 | ○ | ○ | ○ (今と同じ) |
| ピン留め | ○ | ○ | ○ |
| 連合モード・ハッシュタグの変更 | ○ | 要検討 | ○ |
| 収蔵したリモートのノートを外す | ○ | ○ | ○ |
| 管理者の追加・解除 | ○ | × | ○ |
| オーナーの交代 | ○ (相手の承認が要る) | × | ○ (承認なしで付け替えられる) |
| アーカイブ | ○ | × | ○ |

- 管理者はローカルのユーザーに限る
- 管理者を自分でやめる操作を用意する
- 管理者の人数に上限を設ける (例: 10 人)

## 4. 作るもの (案)

### データ

- `channel_moderator` テーブル (チャンネルの ID、ユーザーの ID、追加した日時、追加した人)。チャンネルとユーザーの組で一意にする
  - `channel` に ID の配列で持つ案もあるが、ユーザーの削除や一覧の取得を考えるとテーブルのほうが扱いやすい
- オーナーの交代の申請 (相手が承認するまでの保留) をどこに持つかを決める。通知と承認の API で済むなら、`channel` に `pendingOwnerId` を足すだけでもよい

### API

- `channels/moderators/list`、`channels/moderators/add`、`channels/moderators/remove`
- `channels/transfer-ownership` (申請)、`channels/accept-ownership` (承認)、`channels/reject-ownership` (辞退)
- `channels/remove-note` を戻し、権限の判定を「オーナー・管理者・サーバーのモデレーター」にする
- packed の Channel に、見ている人の役割 (`myRole: 'owner' | 'moderator' | null` など) を足し、画面が権限を判定できるようにする

### 画面

- チャンネルの編集画面に、管理者の一覧と追加・解除、オーナーの交代を足す
- 申請を受けた人に通知を出し、承認・辞退できるようにする
- ノートのメニューの「チャンネル」のサブメニューを、管理者にも出す

### 記録

- サーバーのモデレーターが操作したときは、モデレーションのログに残す (オーナーの付け替え、管理者の解除、ノートを外す操作)
- オーナーや管理者の操作を、チャンネルの中で見える記録として残すかは要検討

## 5. 決めること

1. 管理者に連合モードやハッシュタグの変更を許すか (連合はサーバーの外への影響が大きい)
2. オーナーのアカウントが削除・凍結されたとき、管理者のだれかを自動でオーナーにするか、サーバーのモデレーターが付け替えるまで空けておくか
3. 外したノートを、同じハッシュタグで再び収蔵しないようにするか (外したノートの ID を覚えておくか)
4. ノートを外すだけでなく、特定のリモートのユーザー (またはサーバー) をチャンネルに収蔵しない設定を持たせるか
5. 上流の Misskey に同じような提案や実装がないかを、着手前に調べる

## 6. 前の実装で分かっていたこと

- ローカルのノートは外せないようにしていた。外すと、連合しないチャンネルの `localOnly` のノートが、ローカルタイムラインなどに出てしまうためである
- 外すときは、`notesCount` を 1 減らし、Redis の `channelTimeline`、`userTimelineWithChannel`、チャンネルをフォローしている人の `homeTimeline` / `homeTimelineWithFiles` から外していた
- チャンネルのフォロワーが投稿者もフォローしているときは、外したあとのノートもその人のホームに出るはずだが、Redis からは消えていた (DB からの補充では出る) [推測]。戻すときはここも見直す
